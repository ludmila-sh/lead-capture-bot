# Передача проекта — чек-лист

Что нужно предоставить и сделать, чтобы бот полностью работал под заказчика.
Пункты со `[ ]` — задачи; отмечайте по мере готовности.

---

## 1. Telegram-бот

- [ ] **Создать бота** у [@BotFather](https://t.me/BotFather): `/newbot`, получить `BOT_TOKEN`.
- [ ] Настроить карточку бота в BotFather:
  - [ ] `/setname` — имя (напр. «Ассистент <Имя эксперта>»)
  - [ ] `/setdescription` — текст на экране «что умеет бот» (до первого запуска)
  - [ ] `/setabouttext` — короткое «о боте» в профиле
  - [ ] `/setuserpic` — аватар
  - [ ] `/setcommands` — минимум: `start - начать`
- [ ] Вписать `BOT_TOKEN` в `.env`.

## 2. Эксперт и передача лидов

- [ ] `EXPERT_HANDOFF_USERNAME` — публичный @username эксперта (без `@`). Должен быть
      выставлен в настройках Telegram эксперта («Кто может найти меня по имени»).
- [ ] `EXPERT_CHAT_ID` — числовой id эксперта, чтобы бот **присылал уведомления о лидах**.
  - Эксперт пишет [@userinfobot](https://t.me/userinfobot) → бот возвращает `Id: 123456789`.
  - **Эксперт обязан один раз нажать `/start` у нашего бота** — иначе Telegram не даёт
    боту написать первым, уведомления не дойдут.
- [ ] **Проверка доставки хендоффа** (см. раздел 7, чек-лист запуска).

## 3. Канал

- [ ] `CHANNEL_URL` — ссылка на канал (`https://t.me/имя_канала` или инвайт-ссылка).
- [ ] **Добавить бота администратором канала** — обязательно для учёта подписок.
      Любой набор прав; достаточно «без прав», главное статус «администратор».
      Без этого события `subscribed` / `unsubscribed` не фиксируются.
- [ ] Если канал **приватный** — вписать `CHANNEL_ID` (числовой, вида `-100…`).
      Его видно в консоли бота строкой `bot membership in … (id=…)` сразу после
      добавления бота в канал. Для публичного канала — не нужно.

## 4. Контент (`content/texts.yaml`)

Всё редактируется в одном YAML-файле, код не нужен. Правило: абзац = одна строка,
между абзацами пустая строка; `{link}` в тексте магнита не удалять; `[ ... ]` —
подставить своё. При старте бот проверяет файл и не запустится с явной ошибкой.

- [ ] Реальные ссылки на видео-практики по сегментам: `base`, `spina`, `office`,
      `mama` (`lead_magnets.<key>.link`). `trener` — ссылка на разбор, если есть,
      иначе оставить пустой и убрать `[ссылка …]` из текста.
- [ ] Финальные тексты (черновики уже в голосе Артёма, на «ты» — согласовать с ним):
  - [ ] `screens.greeting`, `menu_prompt`
  - [ ] `lead_magnets.<key>.text` и `.question` для всех сегментов
  - [ ] `faq` — 3–5 вопросов-ответов (цены, Zoom, город — заполнить `[ ... ]`)
  - [ ] `screens.expert`, `handoff_ack`, `health_reply`, `fallback`
- [ ] `health_keywords` — согласовать с Артёмом, что считается «вопросом о здоровье»
      (по таким сообщениям бот не отвечает сам, а зовёт Артёма).
- [ ] Deep-link ссылки для Instagram / ChatPlace: `https://t.me/<bot>?start=spina`
      (и `office`, `mama`, `trener`). Параметр — только латиница/цифры/`_`/`-`.
      **Важно:** сегмент «шея/офис» теперь `office`, не `sheya` — старую ссылку
      `?start=sheya` в ChatPlace заменить на `?start=office`.

## 5. Аналитика в Google Sheets

Подробности — в `README.md` → «Аналитика в Google Sheets».

- [ ] Google Cloud: проект → service account → включить **Google Sheets API**.
- [ ] Скачать JSON-ключ service account → положить в `secrets/` (папка вне git).
- [ ] Создать Google-таблицу; **расшарить** её на `client_email` из ключа как **Editor**.
- [ ] В `.env`: `GOOGLE_SERVICE_ACCOUNT_JSON`, `ANALYTICS_SPREADSHEET_ID` (id из URL
      между `/d/` и `/edit`), `ANALYTICS_WORKSHEET` (напр. `events`).
- [ ] `python -m src.sheets` — проверка связи; печатает `OK …` и формулу для «Сводки».
- [ ] Создать вкладку «Сводка» и вставить формулу из вывода команды.
- [ ] Решить по персональным данным: в таблице лежат `user_id` / `username` / `name`.
      Оставляем как есть или убираем `username`/`name` из общей таблицы (остаются
      только в локальном `data/interactions.jsonl`).

### 5.1 Ручной сбор данных из Instagram (ежемесячно)

Бот видит только Telegram. Охваты и клики из Instagram эксперт вносит руками —
так вся воронка (Instagram → бот → канал → эксперт) собирается в одной таблице.

1. В той же Google-таблице завести вкладку **«Instagram»** со столбцами:
   `месяц | кампания | охват | показы | посещения профиля | клики по ссылке |
   переходы в бот (start) | подписки на канал | заявки эксперту`.
2. Раз в месяц в приложении Instagram (аккаунт должен быть **профессиональным**:
   *Настройки → Тип аккаунта → Переключиться на профессиональный*):
   - *Профиль → Статистика* → период «30 дней» → выписать **охват**, **показы**,
     **посещения профиля**, **клики по ссылке в шапке**.
   - Если ссылка на бота ставится в конкретных сторис/постах — открыть *Статистику*
     этого поста/сторис и взять **клики по ссылке** там.
3. Из бота за тот же месяц взять числа из вкладки «Сводка» (или `python -m src.stats`):
   переходы `start`, `magnet_delivered`, `subscribed`, `handoff` — вписать рядом.
4. Посчитать конверсии: `клики по ссылке → start`, `start → subscribed`,
   `start → handoff`. Это и есть эффективность воронки по месяцам.

Инструменты типа ChatPlace дают свою статистику по ссылкам — её тоже можно
переносить в эту вкладку.

## 6. Хостинг и эксплуатация

- **Сейчас:** бот развёрнут на сервере разработчика (Koyeb). На период поддержки
  (1–3 мес) этого достаточно.
- **Дальше — куда переносить (для не-IT):**
  - **hoster.by** — белорусский VPS, оплата в BYN, поддержка на русском. Нужен
    самый маленький тариф Linux VPS; разработчик разово настраивает автозапуск.
  - Альтернативы: Timeweb, любой VPS 1 ГБ RAM. «Бесплатные» PaaS (Koyeb/Render free)
    засыпают при простое — для бота на long polling не годятся без доработки.
  - Мини-ПК / всегда включённый компьютер эксперта — самый дешёвый вариант, если
    есть стабильный интернет.
- **Что нужно на хосте:** Python 3.11+, файлы `.env` и `secrets/`, автозапуск
  (systemd / Docker / на Windows — `nssm`), ротация логов.
- **Резервные копии:** `data/interactions.jsonl` — локальный журнал всех событий
  (в т.ч. то, что не долетело в Google Sheets). Настроить копирование куда-нибудь.

## 7. Чек-лист запуска (пройти перед передачей)

- [ ] `/start` без параметра → приветствие + меню.
- [ ] `/start spina`, `/start office`, `/start mama`, `/start trener` → нужный
      лид-магнит (сообщение с видео + кнопки «Подписаться» / «В меню»), затем
      вторым сообщением — открытый вопрос.
- [ ] Кнопка «🧘 Бесплатная практика» из меню → лид-магнит по умолчанию (`base`).
- [ ] Раздел «❓ Частые вопросы» → список, ответы, кнопки «назад».
- [ ] Кнопка «💬 Написать Артёму» → **Артёму приходит уведомление** с карточкой
      лида (имя, контакт, id, сегмент, повод). Требует п. 2 (`EXPERT_CHAT_ID` +
      эксперт нажал `/start`).
- [ ] Сообщение «болит спина» (или другое из `health_keywords`) → Артёму приходит
      уведомление «вопрос о здоровье» + пользователю ответ «передал Артёму».
- [ ] Мусорный ввод (стикер, случайный текст, старая кнопка) → бот показывает меню,
      **не падает**.
- [ ] Подписка на канал новым аккаунтом → в консоли `subscribed: user_id=…`,
      в Google-таблице новая строка `subscribed`. Требует п. 3 (бот — админ канала).
- [ ] Отписка от канала → строка `unsubscribed`.
- [ ] В Google-таблице строки появляются в реальном времени; при недоступности
      Google данные всё равно в `data/interactions.jsonl`.
