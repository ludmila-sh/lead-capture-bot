# Передача проекта — чек-лист

Что нужно предоставить и сделать, чтобы бот полностью работал под заказчика.
Пункты со `[ ]` — задачи; отмечайте по мере готовности.

---

## 1. Telegram-бот

- [ ] **Создать бота** у [@BotFather](https://t.me/BotFather): `/newbot`, получить `BOT_TOKEN`.
- [ ] **Username** — без `test`/`dev`, читаемый и близкий к бренду: `@artem_yoga_bot`,
      `@fysom_bot`. Менять потом нельзя, поэтому сразу «боевой».
- [ ] Вписать `BOT_TOKEN` в `.env`.
- [ ] Пройти чек-лист «production-ready» ниже (раздел 1.1).

### 1.1 Как оформить бота «как у блогеров» (BotFather → `/mybots` → выбрать бота)

Всё это делается в [@BotFather](https://t.me/BotFather) командами или через меню
*Bot Settings*. Заполнять **на русском**.

- [ ] **`/setuserpic` — аватар.** Квадрат, лицо крупно и по центру (в чатах кружок
      ~40 px). Фото `docs/profile_photo.jpg` подойдёт, но лучше **обрезать плотно
      по лицу** — на общем плане с горами лицо в кружке будет мелким. Фон
      однотонный/размытый читается лучше.
- [ ] **`/setname` — отображаемое имя.** «Артём Сан · йога» или «Артём — йога-бот».
      Не «bot», не латиница вперемешку.
- [ ] **`/setdescription` — экран до первого запуска** (≤512 симв., показывается
      с большой кнопкой **START** в пустом чате). Продаёт результат + говорит нажать
      Start. Пример:
      > Бесплатная практика от Артёма Сана под твою задачу — спина, шея-плечи или
      > восстановление после родов. Плюс ответы на частые вопросы и запись на
      > занятия. Жми «Start» 👇
- [ ] **`/setabouttext` — «О боте»** (≤120 симв., видно в профиле и при шеринге).
      Пример: «Йога-бот Артёма Сана: бесплатная практика, ответы, запись.»
- [ ] **`/setcommands` — меню команд** (кнопка ☰ у поля ввода). Формат `команда - описание`:
      ```
      start - Практика и меню
      ```
      Больше команд не нужно — вся навигация на inline-кнопках.
- [ ] **Menu Button** (*Bot Settings → Menu Button*) — оставить «commands» (по
      умолчанию) либо задать кнопку «🧘 Открыть меню», ведущую на `/start`.
- [ ] **`/setjoingroups` → Disable** — бота не добавляют в группы (в канал он
      попадает как админ отдельно, это не отсюда).
- [ ] **`/setprivacy` → Enable** (по умолчанию) — не влияет на приватные чаты и на
      учёт подписок (для него бот — админ канала).
- [ ] **`/setinline` — не включать.**
- [ ] **Политика конфиденциальности.** Бот пишет `user_id` / имя / username в
      Google-таблицу — Telegram просит для таких ботов ссылку на политику.
      *Bot Settings → Privacy Policy* → короткая страница (Telegra.ph/Notion):
      что собираем (id, имя, username, действия в боте), зачем (аналитика воронки,
      связь эксперта с лидом), сколько храним, как удалить (написать эксперту).
- [ ] **Проверка вида:** открыть бота с другого аккаунта «с нуля» — аватар,
      имя, описание, кнопка Start, после Start приветствие с фото и меню.

### 1.2 Приветствие и выдача практики

- **`/start` без кодового слова** → одно сообщение: **фото Артёма + приветствие +
  меню**. Файл — `src/content/assets/artem.jpg` (нет файла → просто текст; заменить =
  положить новый `artem.jpg` туда же и перезапустить; не нужен → удалить файл).
- **`/start <кодовое слово>`** (переход из Instagram) → одно сообщение с практикой,
  без фото, + кнопки `[📣 Подписаться на канал]` / `[🏠 В меню]`. Что именно шлём —
  настраивается в `texts.yaml` на каждый сегмент:
  - `link` заполнен, `video` пустой → текст + ссылка на YouTube (Telegram сам
    рисует превью с обложкой; один клик — уводит в YouTube).
  - `video` заполнен (Telegram `file_id` или прямой `.mp4` URL) → видео уходит
    **файлом прямо в чат**, играет внутри Telegram, никуда не уводит.
- **Что выбрать (обсудить с Артёмом):** ссылка проще и нагоняет просмотры на
  YouTube-канал; готовое видео — лучший опыт, но нужен файл (свои ролики, не
  перезалив с YouTube) и один раз загрузить в Telegram, чтобы получить `file_id`
  (длинные видео иначе не проходят по лимиту бота 50 МБ). Как получить `file_id` —
  скажи, добавлю мини-инструкцию.

### 1.3 Кнопка «Подписаться на канал» выдаёт «канал не существует»

Кнопка просто открывает `CHANNEL_URL` из `.env` — бот его не меняет. Если Telegram
говорит «нет такого канала», проверь:
- открой `CHANNEL_URL` в браузере/поиске Telegram — канал существует под этим
  **точным** публичным именем?
- канал **публичный**? Если его сделали приватным, ссылка `t.me/username` перестаёт
  работать — в `CHANNEL_URL` нужен **инвайт-линк** вида `https://t.me/+xxxxxxxx`.
- регистр и опечатки в username.
- (`CHANNEL_ID` для трекинга подписок — отдельно, на кнопку не влияет.)

## 2. Эксперт и передача лидов

- [ ] `EXPERT_HANDOFF_USERNAME` — публичный @username эксперта (без `@`). Должен быть
      выставлен в настройках Telegram эксперта («Кто может найти меня по имени»).
- [ ] `EXPERT_CHAT_ID` — числовой id эксперта, чтобы бот **присылал уведомления о лидах**.
  - Эксперт пишет [@userinfobot](https://t.me/userinfobot) → бот возвращает `Id: 123456789`.
  - **Эксперт обязан один раз нажать `/start` у нашего бота** — иначе Telegram не даёт
    боту написать первым, уведомления не дойдут.
- [ ] **Проверка доставки хендоффа** (см. раздел 7, чек-лист запуска).

## 3. Канал

- [ ] `CHANNEL_URL` — ссылка на канал (`https://t.me/имя_канала` или инвайт-ссылка).
- [ ] **Добавить бота администратором канала** — обязательно для учёта подписок.
      Любой набор прав; достаточно «без прав», главное статус «администратор».
      Без этого события `subscribed` / `unsubscribed` не фиксируются.
- [ ] Если канал **приватный** — вписать `CHANNEL_ID` (числовой, вида `-100…`).
      Его видно в консоли бота строкой `bot membership in … (id=…)` сразу после
      добавления бота в канал. Для публичного канала — не нужно.

## 4. Контент

Два уровня:
- **`src/content/texts.yaml`** — встроенный источник (правит разработчик). Правило:
  абзац = одна строка, между абзацами пустая строка; `[ ... ]` — подставить своё.
- **Вкладка `Тексты бота`** в рабочей таблице — заказчик правит там **без доступа
  к хостингу**. Бот подхватывает сам за ~3 мин или сразу по `/reload` (от админа).
  Пустая ячейка = значение из кода. Битые правки бот не применяет (остаётся на
  рабочих текстах, причина — в лог и в ответ `/reload`). См. `README.md` → «Тексты бота».

- [ ] Реальные ссылки на видео-практики по сегментам: `base`, `spina`, `office`,
      `mama` (`lead_magnets.<key>.link`). `trener` — ссылка на разбор, если есть,
      иначе оставить пустой и убрать `[ссылка …]` из текста.
- [ ] Финальные тексты (черновики уже в голосе Артёма, на «ты» — согласовать с ним):
  - [ ] `screens.greeting`, `menu_prompt`
  - [ ] `lead_magnets.<key>.text` для всех сегментов (`.question` бот не шлёт —
        это шпаргалка для Артёма)
  - [ ] `faq` — 3–5 вопросов-ответов (цены, Zoom, город — заполнить `[ ... ]`)
  - [ ] `screens.expert`, `handoff_ack`, `health_reply`, `fallback`
- [ ] `health_keywords` — согласовать с Артёмом, что считается «вопросом о здоровье»
      (по таким сообщениям бот не отвечает сам, а зовёт Артёма).
- [ ] Deep-link ссылки для Instagram / ChatPlace: `https://t.me/<bot>?start=spina`
      (и `office`, `mama`, `trener`). Параметр — только латиница/цифры/`_`/`-`.
      **Важно:** сегмент «шея/офис» теперь `office`, не `sheya` — старую ссылку
      `?start=sheya` в ChatPlace заменить на `?start=office`.

## 5. Аналитика в Google Sheets

Подробности — в `README.md` → «Аналитика в Google Sheets».

- [ ] Google Cloud: проект → service account → включить **Google Sheets API**.
- [ ] Скачать JSON-ключ service account → положить в `secrets/` (папка вне git).
- [ ] Создать Google-таблицу; **расшарить** её на `client_email` из ключа как **Editor**.
- [ ] Залить **`docs/Fysom — рабочая таблица.xlsx`** в Google Sheets — см. 5.1.
- [ ] В `.env`: `GOOGLE_SERVICE_ACCOUNT_JSON`, `ANALYTICS_SPREADSHEET_ID` (id из URL
      между `/d/` и `/edit`), `ANALYTICS_WORKSHEET=Аналитика` (вкладка так и называется
      в таблице — не переименовывать).
- [ ] `python -m src.sheets` — проверка связи; печатает `OK …`.
- [ ] Живая правка текстов: вкладка `Тексты бота` уже во вложенном файле. В `.env`
      при желании — `TEXTS_RELOAD_SECONDS` (по умолчанию 180) и `ADMIN_IDS`
      (кому можно `/reload`; по умолчанию — `EXPERT_CHAT_ID`). Проверить: поменять
      ячейку → отправить боту `/reload` → бот отвечает `🔁 applied N override(s)`.

### 5.1 Как заменить содержимое таблицы, сохранив ту же ссылку

Чтобы бот и заказчик работали по **той же ссылке**, содержимое существующей
таблицы заменяется на новый файл (сама таблица, её id, доступы — не меняются):

1. Открыть **существующую** Google-таблицу (ту, что в `ANALYTICS_SPREADSHEET_ID`).
2. **Файл → Импорт → Загрузка** → перетащить `Fysom — рабочая таблица.xlsx`.
3. «Место импорта» → **«Заменить таблицу»** → **Импортировать данные**.
   Все текущие вкладки удаляются и заменяются вкладками из файла. Ссылка,
   права доступа и доступ сервисного аккаунта остаются прежними.
4. ⚠️ «Заменить таблицу» **стирает данные**, которые бот уже записал во вкладку
   «Аналитика». Если там есть что сохранить — сначала скопировать строки в
   отдельный лист, после импорта вставить обратно под шапку. На тестовых данных
   можно не заморачиваться.
5. После импорта: открыть `📈 Дашборд` — формулы должны посчитаться (в Google
   Sheets `QUERY`/`UNIQUE` работают; в Excel — нет). Разделитель в формулах
   Google переведёт под локаль сам.
6. `python -m src.sheets` — убедиться, что связь есть и шапка на месте.
7. Перезапустить бота (локально / на сервере) — он продолжит дописывать в
   «Аналитику».

Файл пересобирается командой `python scripts/build_workspace.py` (нужен `openpyxl`)
из `docs/FYSM.xlsx`.
- [ ] Решить по персональным данным: в таблице лежат `user_id` / `username` / `name`.
      Оставляем как есть или убираем `username`/`name` из общей таблицы (остаются
      только в локальном `data/interactions.jsonl`).

### 5.2 Рабочая таблица Fysom — что доработать перед показом заказчику

Файл собирается скриптом `scripts/build_workspace.py` из `docs/FYSM.xlsx`
(нужен `openpyxl`). Что осталось сделать руками в Google Sheets **до** знакомства
заказчика с документом:

- [ ] **Цены** — вкладка `📌 Старт` (блок «ЦЕНЫ») и вкладка `Тексты бота` (строки
      `faq.1.a` «Сколько стоит?», `faq.4.a` «Как оплатить?»): реальные суммы.
- [ ] **Zoom / город** — `Тексты бота`, строка `faq.2.a` «Где проходят занятия».
- [ ] **Вкладка `📈 Дашборд`** — открыть в Google Sheets и убедиться, что формулы
      посчитались (`QUERY`/`UNIQUE`/`FILTER` работают только в Google Sheets, не в
      Excel). В русской локали Google сам переведёт разделитель в `;`.
- [ ] **`💬 Скрипты Instagram`** — перенесена из старого файла как есть, возможны
      смещённые колонки; это отдельная система (ChatPlace), не бот.
- [ ] **`👥 Клиенты`** — удалить строку-пример `@maria_y`, оставить пустой шаблон.
      Статусы: `Лид` / `Пробное` / `Активен` / `Ушёл` (на них завязан Дашборд).
- [ ] **Instagram-вкладка (раздел 5.3)** — завести и объяснить заказчику, что туда
      он раз в месяц вносит охваты/клики руками.
- [ ] Переименовать сам документ в Google Drive (напр. «Fysom — рабочая таблица»).
- [ ] Пройтись по каждой вкладке со строкой «как пользоваться» (строка 2) —
      проверить, что заказчику понятно, что он заполняет, а что считается само.

О чём подумать:
- Нужен ли заказчику доступ на **редактирование** всей таблицы или только части
  (можно защитить вкладки `📈 Дашборд` и `Аналитика` от правок).
- `ТРЕНЕР` в `📌 Старт` — оставляем ли этот сегмент в передаче или убираем до
  отдельного этапа.

### 5.3 Ручной сбор данных из Instagram (ежемесячно)

Бот видит только Telegram. Охваты и клики из Instagram эксперт вносит руками —
так вся воронка (Instagram → бот → канал → эксперт) собирается в одной таблице.

1. В той же Google-таблице завести вкладку **«Instagram»** со столбцами:
   `месяц | кампания | охват | показы | посещения профиля | клики по ссылке |
   переходы в бот (start) | подписки на канал | заявки эксперту`.
2. Раз в месяц в приложении Instagram (аккаунт должен быть **профессиональным**:
   *Настройки → Тип аккаунта → Переключиться на профессиональный*):
   - *Профиль → Статистика* → период «30 дней» → выписать **охват**, **показы**,
     **посещения профиля**, **клики по ссылке в шапке**.
   - Если ссылка на бота ставится в конкретных сторис/постах — открыть *Статистику*
     этого поста/сторис и взять **клики по ссылке** там.
3. Из бота за тот же месяц взять числа из вкладки «Сводка» (или `python -m src.stats`):
   переходы `start`, `magnet_delivered`, `subscribed`, `handoff` — вписать рядом.
4. Посчитать конверсии: `клики по ссылке → start`, `start → subscribed`,
   `start → handoff`. Это и есть эффективность воронки по месяцам.

Инструменты типа ChatPlace дают свою статистику по ссылкам — её тоже можно
переносить в эту вкладку.

## 6. Хостинг и эксплуатация

- **Сейчас:** бот развёрнут на сервере разработчика (Koyeb). На период поддержки
  (1–3 мес) этого достаточно.
- **Дальше — куда переносить (для не-IT):**
  - **hoster.by** — белорусский VPS, оплата в BYN, поддержка на русском. Нужен
    самый маленький тариф Linux VPS; разработчик разово настраивает автозапуск.
  - Альтернативы: Timeweb, любой VPS 1 ГБ RAM. «Бесплатные» PaaS (Koyeb/Render free)
    засыпают при простое — для бота на long polling не годятся без доработки.
  - Мини-ПК / всегда включённый компьютер эксперта — самый дешёвый вариант, если
    есть стабильный интернет.
- **Что нужно на хосте:** Python 3.11+, файлы `.env` и `secrets/`, автозапуск
  (systemd / Docker / на Windows — `nssm`), ротация логов.
- **Резервные копии:** `data/interactions.jsonl` — локальный журнал всех событий
  (в т.ч. то, что не долетело в Google Sheets). Настроить копирование куда-нибудь.

## 7. Чек-лист запуска (пройти перед передачей)

- [ ] `/start` без параметра → приветствие + меню.
- [ ] `/start spina`, `/start office`, `/start mama`, `/start trener` → нужный
      лид-магнит (сообщение с видео + кнопки «Подписаться» / «В меню»), затем
      вторым сообщением — открытый вопрос.
- [ ] Кнопка «🧘 Бесплатная практика» из меню → лид-магнит по умолчанию (`base`).
- [ ] Раздел «❓ Частые вопросы» → список, ответы, кнопки «назад».
- [ ] Кнопка «💬 Написать Артёму» → **Артёму приходит уведомление** с карточкой
      лида (имя, контакт, id, сегмент, повод). Требует п. 2 (`EXPERT_CHAT_ID` +
      эксперт нажал `/start`).
- [ ] Сообщение «болит спина» (или другое из `health_keywords`) → Артёму приходит
      уведомление «вопрос о здоровье» + пользователю ответ «передал Артёму».
- [ ] Мусорный ввод (стикер, случайный текст, старая кнопка) → бот показывает меню,
      **не падает**.
- [ ] Подписка на канал новым аккаунтом → в консоли `subscribed: user_id=…`,
      в Google-таблице новая строка `subscribed`. Требует п. 3 (бот — админ канала).
- [ ] Отписка от канала → строка `unsubscribed`.
- [ ] В Google-таблице строки появляются в реальном времени; при недоступности
      Google данные всё равно в `data/interactions.jsonl`.

## 9. Файлы, которые НЕ коммитятся и передаются отдельно

- `.env` — все токены и ключи (передать заказчику в защищённом виде).
- `secrets/` — JSON-ключ service account Google.
- `data/` — журнал взаимодействий (накопленная история).
